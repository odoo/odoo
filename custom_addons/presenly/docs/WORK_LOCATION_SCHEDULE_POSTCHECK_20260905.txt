- New model: presenly.work.location.schedule.

- Overlapping slots for the same employee and schedule scope are rejected.

LOCATION RESOLUTION PRIORITY
1. Specific Date time slot.
2. Weekly time slot.
3. Native hr.employee.location exception.
4. Native weekday Work Location.
5. Employee primary Work Location fallback.
- If slots exist for a day but none match the current time, check-in is rejected.
- Check-out remains bound to the Work Location snapshot selected at check-in.

UI

- Employee smart button: Location Schedules.
- Attendance and Attendance Evidence expose the selected Schedule snapshot.
- No active or compatibility Additional Work Location menu remains.

API
- Check-in resolves only the slot active in the employee effective timezone.
- work_location_id may be supplied but must match the active schedule.
- Check-in response includes schedule_id or false when using native fallback.
- unit_id remains a transitional alias for native hr.work.location ID.
