## 1. บทสรุป (Summary)

หน้า `/employee-portal` วันนี้เป็น "แผงลิงก์" ที่รวมประกาศ + จองห้องประชุม + การ์ดเมนูด่วน 11 ใบ แต่ยังขาด **"อารมณ์ร่วม" (emotional engagement)** เพราะ 3 สาเหตุ:

1. **ไม่มี "เรื่องของฉัน"** — หน้าเดียวกันสำหรับทุกคน ไม่รู้จักบริบทของแต่ละคน ณ วันนั้น (ลงเวลาแล้วหรือยัง, มีงานค้างอะไร, วันนี้มีอะไรเกิดขึ้น)
2. **บริบทขาดตอน** — การ์ดส่วนใหญ่เด้งออกจากหน้าเว็บไปหน้า backend (`/web#action=...`) ทำให้รู้สึกว่า portal เป็นแค่ทางผ่าน
3. **โทนเป็นทางการล้วน** — ไม่มีการเฉลิมฉลอง ไม่มีการขอบคุณ ไม่มีความเป็นทีม

งานนี้จึงเพิ่ม 3 ชั้นบนหน้าเดิม โดย **ไม่รื้อของเดิมที่ทำงานได้อยู่แล้ว**:

| ธีม | ชื่อ | แก่น | ที่อยู่ |
|---|---|---|---|
| **1** | Personal Touch Layer | "เรื่องของฉัน" — ทักทายตามเวลา + สรุปสถานะส่วนตัววันนี้ | `od19_website` |
| **3** | Daily Companion | "เพื่อนคู่ทุกวัน" — ลงเวลา/ตารางของฉัน/ลิงก์ที่ใช้บ่อย | `od19_website` |
| **2** | Recognition & Belonging | ขอบคุณ/ชื่นชมเพื่อน + อวยพรวันเกิด/วันครบรอบ | `od19_recognition` (ใหม่) |

**เป้าหมายเชิงผลลัพธ์**

- เปิดหน้าแล้วเห็น "ของฉัน" ทันทีภายใน 1 หน้าจอแรก โดยไม่ต้องกดอะไร
- อย่างน้อย 1 อย่างที่ผู้ใช้ "อยากกลับมาเปิดทุกวัน" (ลงเวลา + ตารางของฉัน)
- มีช่องทางแสดงความขอบคุณ/เฉลิมฉลองในที่ทำงาน โดยไม่ต้องผ่าน HR
- หน้าเร็วเหมือนเดิม (โหลดแผงหนักแบบ lazy + cache ต่อผู้ใช้)

**ไม่แตะ** Odoo core · ไม่แตะหน้าเว็บการตลาด (`/`, `/about`, `/products`, `/careers`) · ไม่แตะ flow อนุมัติ/บัญชี

## 3. ความต้องการ (Requirements)

- **R1** Hero ทักทายตามช่วงเวลา (เช้า/บ่าย/เย็น) + ชื่อ + ตำแหน่ง/แผนก + อักษรย่อ (avatar) เมื่อไม่มีรูป
- **R2** แถบ "วันนี้ของฉัน" (My Day Strip) แสดงอย่างน้อย: สถานะลงเวลาวันนี้, งานรออนุมัติของฉัน, นัด/การจองห้องถัดไป, จำนวนวันลาคงเหลือ (ถ้ามีโมดูลลา)
- **R3** โหลดข้อมูลส่วนตัวแบบ **lazy JSON + cache ต่อผู้ใช้ (TTL 60s)** — หน้าแรกต้องเรนเดอร์ได้เร็วแม้ยังไม่โหลดตัวเลข
- **R4** ธีม 3: มีส่วน "ตารางของฉัน" รวมนัด/วันลา/วันหยุด และทางลัดที่ใช้บ่อยที่สุดอยู่ในจอแรก
- **R5** ธีม 2: ให้ Kudos (ขอบคุณ/ชื่นชม) เพื่อนร่วมงานได้ + มีฟีด Kudos ล่าสุด (เฉพาะข้อมูลสาธารณะ)
- **R6** ธีม 2: แสดงวันเกิด/วันครบรอบการทำงานของเพื่อนร่วมงานในเดือนนี้ + อวยพรได้
- **R7** ทุกอย่างเป็น **additive** — ถอน `od19_recognition` แล้วหน้า portal ต้องยังทำงานได้
- **R8** ไม่แตะ Odoo core; ปรับเฉพาะ `custom_addons/`
- **R9** ใช้โทเคนแบรนด์เดิม (`#9E2424`, `#f39200`) และฟอนต์ Sarabun — ไม่เพิ่มชุดสีใหม่
- **R10** Responsive: จอแรกใช้ได้จริงบนมือถือ (เรียงจากสำคัญ → รอง)
- **R11** ไม่มีการอนุมัติ/จ่ายเงินในหน้า portal (ยึดหลัก "view-only + ให้ทุกอย่างที่ต้องตัดสินใจไหลไปหน้าเดิม")
- **R12** มี Unit Test ครอบคลุม logic ฝั่ง server (aggregate + security) และไม่กระทบโมดูลอื่น

## 5. แนวทางที่เลือกและเหตุผล

ผู้ใช้เลือก 3 ธีมรวมกัน โดยจัดลำดับ **1 → 3 → 2**:

1. **ธีม 1 (Personal Touch Layer)** — ให้ผลตอบแทนต่อความพยายามสูงสุด และเป็นฐานให้ธีมอื่นวางต่อ (ทุกอย่างยึด "ของฉัน")
2. **ธีม 3 (Daily Companion)** — สร้างนิสัย "เปิดทุกวัน" จากข้อมูลที่มีอยู่แล้ว (`hr.attendance`) ไม่ต้องเก็บข้อมูลใหม่
3. **ธีม 2 (Recognition & Belonging)** — ให้ผลทางอารมณ์แรงสุด แต่ต้องมีโมเดลข้อมูลใหม่ จึงทำเป็นโมดูลแยกและวางท้าย

**ทางเลือกที่พิจารณาแล้วไม่เลือก**

- รวมธีม 2 เข้า `od19_website` ตรง ๆ → ปฏิเสธ เพราะทำให้ถอน/ปิดฟีเจอร์สังคมไม่ได้ และตัวโมดูลใหญ่ขึ้นโดยไม่จำเป็น
- ทำธีม 2 เป็นหน้าแยกเต็มรูปแบบ (`/my/recognition` เท่านั้น) → ปฏิเสธ เพราะไม่ถูกเปิดบ่อย จะไม่เกิดอารมณ์ร่วม; เลือกทำเป็น **บล็อกสั้นบนหน้าแรก** + มีหน้าเต็มสำหรับดูทั้งหมด

## 6. สถาปัตยกรรมเชิงเทคนิค (Technical Design)

### 6.1 เส้นทาง (Routes)

**`od19_website` (ปรับ/เพิ่ม)**

| Route | Method | คำอธิบาย |
|---|---|---|
| `/employee-portal` | GET | หน้าเดิม — เพิ่มตัวแปรบริบท + โครงหน้าใหม่ |
| `/employee-portal/me-summary` | GET (JSON) | **ใหม่** — สรุป "วันนี้ของฉัน" (ลงเวลา/งานค้าง/นัดถัดไป/วันลา) cache ต่อผู้ใช้ TTL 60s |

**`od19_recognition` (ใหม่)**

| Route | Method | คำอธิบาย |
|---|---|---|
| `/my/recognition` | GET | หน้าฟีด Kudos เต็ม (portal) |
| `/my/recognition/give` | POST | สร้าง Kudos (CSRF, ตรวจสิทธิ์) |
| `/my/recognition/summary` | GET (JSON) | บล็อกสั้นบนหน้าแรก: ฟีด 3–5 รายการ + วันเกิด/วันครบรอบเดือนนี้ (cache ต่อผู้ใช้ TTL 60s) |

**หลักการ:** ทุก route ที่ใช้ `auth="user"` และ `website=True`; JSON endpoint ใช้ `request.make_json_response` ตามแบบ `/my/approvals/summary`

### 6.2 การรวมข้อมูล "วันนี้ของฉัน" (`me-summary`)

คำนวณแบบ *defensive* — โมดูลไหนไม่มี ให้ข้าม field นั้น ไม่ error:

| ข้อมูล | แหล่ง | เงื่อนไข |
|---|---|---|
| สถานะลงเวลาวันนี้ (เข้า/ออก/ชั่วโมง) | `hr.attendance` (ผ่าน ZKTeco) | มี `hr_attendance` |
| งานรออนุมัติของฉัน | มีอยู่แล้วใน `/my/approvals/summary` | ใช้ payload เดิม ไม่คำนวณซ้ำ |
| นัด/การจองห้องถัดไป | `_od19_my_upcoming_bookings()` (มีอยู่) | — |
| วันลาคงเหลือ | `hr.leave` / `hr.leave.allocation` | มี `hr_holidays` |
| ประกาศที่ยังไม่อ่าน | `od19_announcement` | — |

> **หมายเหตุการ implement:** ชื่อฟิลด์/โมเดลจริงของ HR ใน Odoo 19 (เช่น ที่อยู่ของ `birthday`, `hire_date` และโครง `hr.version`) ต้อง **ยืนยันกับซอร์สจริงก่อนเขียนโค้ด** — ระบุเป็น task ตรวจสอบในแผน

### 6.3 โมเดลข้อมูลใหม่ (`od19_recognition`)

**`od19.recognition`** (Kudos 1 ครั้ง = 1 ระเบียน)

| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| `author_id` | m2o `hr.employee` | ผู้ให้ (default = พนักงานปัจจุบัน) |
| `recipient_id` | m2o `hr.employee` | ผู้รับ (required) |
| `badge_id` | m2o `od19.recognition.badge` | ป้ายที่ให้ |
| `message` | Text | ข้อความขอบคุณ (required, จำกัดความยาว) |
| `company_id` | m2o `res.company` | multi-company |
| `published_date` | Datetime | วันเผยแพร่ |
| `is_public` | Boolean | แสดงบนฟีดสาธารณะ (default True) |

**`od19.recognition.badge`** (ป้าย)

| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| `name`, `description` | Char / Text | ชื่อ/คำอธิบายป้าย |
| `icon` | Char | คลาส Font Awesome (เช่น `fa-handshake-o`) |
| `color` | Char | โทนสี (ใช้พาเลตต์แบรนด์) |
| `sequence` | Integer | ลำดับแสดง |

**Security (SoD)**

- อ่าน: ผู้ใช้ภายในที่ล็อกอิน (เฉพาะ `is_public = True` หรือเป็นผู้เกี่ยวข้อง)
- สร้าง: พนักงานทุกคน สร้างในนามตัวเอง (`author_id` = พนักงานปัจจุบัน บังคับที่ server)
- แก้/ลบ: เฉพาะเจ้าของ (หรือ HR manager ตามนโยบาย)
- บังคับ `company_id` ตาม company ปัจจุบัน

### 6.4 แพตเทิร์นประสิทธิภาพ

- หน้าแรกเรนเดอร์ด้วยข้อมูลเบาที่มีอยู่แล้ว (ประกาศ/ห้องประชุม/การจองของฉัน) → ส่วนที่หนัก (me-summary, recognition feed) โหลด **หลังเรนเดอร์** ผ่าน `fetch()` ไปที่ JSON endpoint
- JSON endpoint ใช้ **cache ต่อผู้ใช้ (in-process dict) TTL 60s** ตามแบบ `APPROVAL_SUMMARY_CACHE` — ลดการสแกนซ้ำ
- CSS ใหม่ต่อท้ายไฟล์เดิม; JS เบา (vanilla) เพิ่มเป็น asset ใหม่ใน `web.assets_frontend`

### 6.5 การแทรกบล็อกจาก `od19_recognition` (additive)

- `od19_recognition` ประกาศ `depends = ['od19_website', 'hr', 'mail', 'portal']`
- ใช้ `xpath` ใน `od19_website.od19_employee_portal` เพื่อแทรก `<t t-call="od19_recognition.portal_wall_strip"/>` ต่อจากบล็อกที่กำหนด (ใช้ anchor ที่มี id ชัดเจน เช่น `<div id="od19-recognition-anchor"/>` ที่ `od19_website` เตรียมไว้)
- ถอนโมดูล → template ของ `od19_website` ยังสมบูรณ์ (บล็อกหายไปเฉย ๆ)

### 7.2 ธีม 1 — Personal Touch Layer

- **Hero ตามช่วงเวลา:** ข้อความเปลี่ยนตามเวลาทำการ (08:00–12:00 "สวัสดีตอนเช้า", 12:00–17:00 "สวัสดีตอนบ่าย", หลัง 17:00 "สวัสดีตอนเย็น") + อักษรย่อจากชื่อ (ถ้าไม่มีรูป) + ตำแหน่ง/แผนก
- **My Day Strip:** 4 การ์ดสั้น แต่ละใบมี 1 ตัวเลขสำคัญ + 1 บรรทัดอธิบาย + ลิงก์ไปหน้าที่เกี่ยวข้อง (ไม่เด้งเงียบ)
  - ลงเวลาวันนี้ — "เข้า 08:03 · ออก —" (อ่านจาก `hr.attendance`)
  - รออนุมัติ — ใช้ badge ที่มีอยู่ (`/my/approvals/summary`)
  - นัดถัดไป — จาก `my_bookings`
  - วันลาคงเหลือ — "เหลือ 6 วัน" (ถ้ามี `hr_holidays`)

### 7.3 ธีม 3 — Daily Companion

- **ตารางของฉัน:** ไทม์ไลน์ย่อของวันนี้ → สัปดาห์นี้ รวม: การจองห้องของฉัน, วันลาที่ได้รับอนุมัติ, วันหยุดบริษัท (ถ้ามีแหล่งข้อมูล)
- **ทางลัดใช้บ่อย:** ยกระบบ "ใช้บ่อย" ขึ้นมาเป็นปุ่มใหญ่ 4 ปุ่มในจอแรก (เช่น ลงเวลา/ดูตาราง, เปิดอนุมัติ, ยื่นค่าใช้จ่าย, จองห้อง) โดยอิงจากของที่มีอยู่
- **การจัดกลุ่มเมนูด่วน [G]:** จัด 11 การ์ดเดิมเป็น 3 กลุ่มตามหน้าที่ (งานของฉัน / HR & สวัสดิการ / ความรู้ & แจ้งปัญหา) — ลดความแบนของรายการ

### 7.4 ธีม 2 — Recognition & Belonging (`od19_recognition`)

- **ให้ Kudos:** ฟอร์มสั้น (เลือกเพื่อน → เลือกป้าย → พิมพ์ข้อความ) ส่งผ่าน portal POST + CSRF
- **ฟีด Kudos:** 3 รายการบนหน้าแรก + หน้าเต็ม `/my/recognition`; เรียงตามวันเผยแพร่; เฉพาะข้อมูลสาธารณะ
- **อวยพร:** แถบเล็ก "🎂 เดือนนี้" รวมคนที่วันเกิด/วันครบรอบการทำงานในเดือนนี้ + ปุ่ม "อวยพร" (สร้าง Kudos แบบเร็วเลือกป้าย "Happy Birthday / Happy Anniversary")

## 11. ความปลอดภัย (Security)

- ทุก route `auth="user"` + `website=True`; POST ต้องมี CSRF
- บังคับ `author_id` / `company_id` ที่ฝั่ง server เสมอ (ห้ามเชื่อค่าจากฟอร์ม)
- Record rule: อ่านเฉพาะ `is_public = True` หรือเป็นผู้เกี่ยวข้อง; แก้/ลบเฉพาะเจ้าของ
- ไม่ expose ข้อมูลอ่อนไหว (เงินเดือน/ข้อมูลส่วนตัว) บนหน้า portal
- ไม่มี action อนุมัติ/จ่ายเงินในหน้า portal (ตามหลัก Zero Trust / ไม่มีการอนุมัติสินเชื่อ-ไม่มีการจ่ายเงิน)
