# เอกสารออกแบบ: ระบบเบิกค่าใช้จ่ายพนักงาน (Employee Expense Reimbursement) — Odoo 19 CE

- **วันที่:** 2026-11-06 (rev3 — เพิ่ม Mileage + สมุดรถประจำตัวพนักงาน)
- **โมดูลที่แตะ:** สร้างใหม่ `od19_hr_expense_portal`; แก้ `od19_hr_expense_thai`, `od19_hr_expense_enhanced`, `od19_approval_center`, `od19_role_catalog` (ไม่แตะ Odoo core)
- **สถานะ:** รอตรวจสอบ (Draft for review)
- **ผู้เกี่ยวข้อง:** พนักงานผู้เบิก / หัวหน้าแผนก / ฝ่ายบัญชี / CEO / ฝ่ายไอที–แอดมิน
- **แนวทางที่เลือก:** A — ต่อยอดบนเครื่องยนต์เดิม (`hr.expense` + `od19_hr_expense_enhanced` + `od19_hr_expense_thai`)

---

## 1. บทสรุป (Summary)

โปรเจกต์นี้มี "เครื่องยนต์" สำหรับค่าใช้จ่ายพนักงานอยู่ครบแล้ว ได้แก่ โมดูล core `hr.expense` (CE), `od19_hr_expense_enhanced` (เอกสารไทย/VAT/เบี้ยเลี้ยง/เงินสด) และ `od19_hr_expense_thai` (จ่ายคืนพนักงานจริง + reconcile) แต่ยังขาดสองสิ่งตามความต้องการของผู้ใช้:

1. **ความง่ายในการใช้งานของพนักงาน** — ปัจจุบัน `hr.expense` เป็นหน้าจอหลังบ้าน (backend) ล้วน ไม่มี portal และมีรายละเอียดภาษี/บัญชีที่พนักงานทั่วไปไม่จำเป็นต้องเข้าใจ
2. **การอนุมัติ 3 ชั้น** — ปัจจุบันมีเพียง 2 ชั้น (กลไกฟิลด์ `first_approver_id` / `second_approval_state`)

งานนี้จึง **ไม่สร้างโมเดลใหม่** แต่เพิ่ม "ชั้นประสบการณ์ใช้งานของพนักงาน" และ **ยกระดับการอนุมัติเป็น 3 ชั้น** (หัวหน้าแผนก → บัญชี → CEO) ด้วย OCA `base_tier_validation` ซึ่งมีฟีเจอร์ส่งต่อการอนุมัติ (Forward) ให้ผู้อื่นในกลุ่มทำแทนได้ ผ่านโมดูล `base_tier_validation_forward`

**เป้าหมายเชิงผลลัพธ์**

- พนักงานยื่นใบเบิกได้จบใน ≤ 4 ขั้นตอน โดยไม่ต้องรู้เรื่องภาษี/บัญชี
- รองรับการเบิก **ค่าเดินทางตามระยะทาง (Mileage)** ด้วยอัตราต่อกิโลเมตรเดียวทั้งบริษัท โดยพนักงานกรอกแค่ระยะทางและข้อมูลรถ ระบบคำนวณยอดให้
- ระบบ **จดจำรถของพนักงาน** (ประเภท + ป้ายทะเบียน) แล้วเติมให้อัตโนมัติในครั้งถัดไป (ใช้คันล่าสุดก่อน) พร้อมแก้ไข/เพิ่ม/ลบได้
- ใบเบิกทุกใบผ่านการอนุมัติครบ 3 ชั้นตามลำดับ และมอบหมายแทนกันได้ผ่านเมนู Tier Validation
- ใช้ได้ทั้งหลังบ้านและพอร์ทัล และใช้งานบนมือถือได้
- ไม่ทิ้งงานบัญชี/ภาษีที่ทำเสร็จแล้ว และไม่แตะ Odoo core

## 3. ความต้องการ (Requirements)

- **R1** พนักงานยื่นใบเบิกได้จบใน ≤ 4 ขั้นตอน และไม่ต้องป้อนข้อมูลภาษี/บัญชีเอง
- **R2** ใบเบิกทุกใบต้องผ่านการอนุมัติครบ **3 ชั้นตามลำดับ**: หัวหน้าแผนก → บัญชี → CEO
- **R3** ผู้อนุมัติมอบหมายให้ผู้อื่นทำแทนได้ โดยตั้งค่าผ่านเมนู Tier Validation (ของ OCA ที่มีอยู่)
- **R4** รองรับการใช้งานทั้ง backend และ portal (พอร์ทัลพนักงาน) และใช้งานบนมือถือได้
- **R5** แนบรูป/ไฟล์ใบเสร็จหรือเอกสารประกอบได้
- **R6** รองรับคุณสมบัติภาษีไทยครบ: VAT (ภาษีซื้อ), WHT, ใบรับรองแทนใบเสร็จรับเงิน, เบี้ยเลี้ยง ม.42(3)
- **R7** จ่ายคืนพนักงานจริงผ่าน `account.payment` และ reconcile ปิดยอดเจ้าหนี้
- **R8** ผู้ใช้พอร์ทัลเห็นเฉพาะใบเบิกของตัวเอง
- **R9** ไม่แตะ Odoo core; ทุกอย่างเป็นแบบ additive
- **R10** รองรับการเบิก **ค่าเดินทางตามระยะทาง (Mileage)**: พนักงานกรอกระยะทาง (กม.) + ประเภทยานพาหนะ + ป้ายทะเบียน + ต้นทาง/ปลายทาง ระบบคำนวณยอด = ระยะทาง × อัตราต่อ กม. (อัตราเดียวทั้งบริษัท ตั้งค่าที่บริษัท) โดยไม่ต้องกรอกภาษี/บัญชี
- **R11** มีปุ่มช่วยคำนวณระยะทางจากแผนที่ (optional) แต่ยังกรอกเองได้เสมอ เพื่อให้ทำงานได้แม้ไม่มีเน็ต
- **R12** ระบบ **จดจำรถของพนักงานแต่ละคน** (ประเภท + ป้ายทะเบียน) โดย
  - เมื่อพนักงานกรอกข้อมูลรถครั้งแรก ระบบบันทึกไว้ผูกกับพนักงานคนนั้น
  - ครั้งถัดไปที่เบิก ระบบ **เติมข้อมูลรถให้อัตโนมัติ** — ถ้ามีหลายคัน ใช้ **คันที่ใช้ล่าสุด** ก่อน
  - พนักงาน **แก้ไข / เพิ่ม / ลบ** รถของตัวเองได้ตลอด
  - รายการรถเห็นได้เฉพาะเจ้าของ (และฝ่ายที่ดูแล) ไม่ปนกับพนักงานคนอื่น

## 6. UX ฝั่งพนักงาน (หัวใจของ "ใช้งานง่าย")

### 6.1 หลักการ

- **พนักงานไม่ต้องรู้เรื่องภาษี/บัญชี** — ระบบตั้งค่าเริ่มต้น (VAT/WHT/ประเภทเอกสาร/บัญชี) ให้อัตโนมัติจาก "หมวดค่าใช้จ่าย" (product) ของใบเบิก
- **ขั้นตอนน้อยที่สุด**: ประเภท → จำนวนเงิน + วันที่ → แนบรูป → ส่ง
- **เห็นสถานะชัด**: บอกว่า "รอใคร" (หัวหน้าแผนก/บัญชี/ผู้บริหาร) ไม่ใช่แค่ "submitted"

### 6.2 Backend (พนักงานที่มีบัญชี Odoo)

- เมนูใหม่ **"ยื่นใบเบิกค่าใช้จ่าย"** เปิด wizard ฟอร์มย่อ 4 ขั้น (สร้าง `hr.expense` เป็น `draft` แล้วให้ผู้ใช้กดส่ง หรือส่งทันทีตามที่เลือก)
- หน้า Kanban **"ใบเบิกของฉัน"** จัดกลุ่มตามสถานะ และแสดงป้ายผู้อนุมัติปัจจุบัน

### 6.3 Portal (พนักงานที่ไม่มีสิทธิ์หลังบ้าน)

- Route `/my/expenses` (รายการ) และ `/my/expenses/new` (ฟอร์ม) ใช้ `portal.portal_layout`

### 6.5 Mileage — การเบิกค่าเดินทางตามระยะทาง (ประสบการณ์พนักงาน)

พนักงานเลือก "หมวดค่าใช้จ่าย" = **ค่าเดินทาง (Mileage)** แล้วกรอกเฉพาะช่องที่จำเป็น

| ช่อง | รายละเอียด | ที่มา |
|---|---|---|
| ระยะทาง (กม.) | ตัวเลขเท่านั้น | พนักงานกรอกเอง (หรือกดปุ่มคำนวณ) |
| **รถของฉัน** (ประเภทยานพาหนะ + ป้ายทะเบียน) | เลือกจาก "สมุดรถของฉัน" หรือเพิ่มคันใหม่ได้ทันที | ระบบเติมคันล่าสุดให้อัตโนมัติ (ดู §6.6) |
| ต้นทาง / ปลายทาง | ข้อความสั้น | พนักงานกรอกเอง |
| วันที่เดินทาง | วันที่ | พนักงานเลือก |
| **ยอดเงิน** | คำนวณให้อัตโนมัติ = ระยะทาง × อัตราต่อ กม. | ระบบ (read-only ให้พนักงานเห็น) |

- **ไม่ต้องกรอกภาษี/บัญชี** — Mileage เป็นการจ่ายคืนค่าพาหนะตามจริง ไม่มี VAT และไม่หัก ณ ที่จ่าย (ดู §9)
- **ปุ่ม "คำนวณระยะทางจากแผนที่"** (Phase 4, optional): เติมช่องระยะทางให้จากต้นทาง–ปลายทาง ถ้าบริษัทตั้งค่า API key ไว้; ถ้าไม่มีหรือเรียกไม่สำเร็จ ให้พนักงานกรอกเองได้ทันที (ไม่บล็อกการส่ง)
- ทั้ง wizard ฝั่งหลังบ้านและฟอร์มพอร์ทัลใช้ชุดช่องเดียวกัน และแสดงยอดที่คำนวณให้ทันทีเพื่อให้พนักงานตรวจสอบก่อนส่ง

### 6.6 สมุดรถประจำตัวพนักงาน (Vehicle Book) — จดจำ + เติมอัตโนมัติ

- เก็บรถของพนักงาน **แยกเป็นรายคัน** ผูกกับ `hr.employee` (โมเดลใหม่ `od19.employee.vehicle`: ประเภท, ป้ายทะเบียน, เจ้าของ, วันที่มีการใช้งานล่าสุด, สถานะใช้งาน)
- **ครั้งแรก:** พนักงานเลือก "เพิ่มคันใหม่" ในช่องรถของใบเบิก → ระบบบันทึกเข้าสมุดรถของพนักงานคนนั้นทันที
- **ครั้งถัดไป:** ระบบ **เติมรถให้อัตโนมัติ** เมื่อเปิดใบเบิกแบบ Mileage
  - ถ้ามีรถในสมุด **1 คัน** → เติมคันนั้น
  - ถ้ามี **มากกว่า 1 คัน** → เติม **คันที่ใช้ล่าสุด** (เรียงตาม "วันที่มีการใช้งานล่าสุด" แล้วจึงวันที่สร้าง)
- **แก้ไข / เพิ่ม / ลบ:** พนักงานจัดการรถของตัวเองได้ในฟอร์มใบเบิก (แก้ inline / เพิ่มคันใหม่ / ลบ) และดู/จัดการทั้งหมดได้ที่เมนู **"รถของฉัน"**
- **การมองเห็น (visibility):** พนักงานเห็นเฉพาะรถของตัวเอง; งานที่อนุมัติแล้วจะเก็บ **สำเนาข้อมูลรถ ณ เวลาที่เบิก** (ประเภท + ป้ายทะเบียน) เพื่อไม่ให้ประวัติเดิมเปลี่ยนตามการแก้ไขสมุดรถภายหลัง
- **การใช้งาน:** หากพนักงานย้ายแผนกหรือเปลี่ยนงาน ระบบยังจำรถตามพนักงานคนนั้น (ผูกกับ `hr.employee` ตรง ๆ)

## 8. การอนุมัติ 3 ชั้น (OCA `base_tier_validation`)

- เพิ่ม mixin `tier.validation` เข้า `hr.expense` (ผ่าน `od19_hr_expense_thai`)
- นิยาม `tier.definition` 3 รายการ เงื่อนไข `[(1,'=',1)]` (ทุกใบ) โดยเรียงตาม `sequence`:

| ลำดับการอนุมัติ | ชั้น | กลุ่มผู้อนุมัติ | `sequence` (definition) |
|---|---|---|---|
| 1 (ก่อน) | หัวหน้าแผนก | `hr_expense.group_hr_expense_manager` | 30 |
| 2 | ฝ่ายบัญชี | `account.group_account_manager` | 20 |
| 3 (สุดท้าย) | CEO | กลุ่มใหม่ `Expense CEO Approver` | 10 |

> **กลไกที่ต้องยืนยันตอน implement:** `base_tier_validation` เรียง `tier.definition` ด้วย `sequence` จากมากไปน้อยไปเป็น `tier.review.sequence` 1, 2, 3 (definition `sequence` สูงกว่า = อนุมัติก่อน) ตามที่โปรเจกต์ใช้ใน `od19_hr_advance` — ต้องตรวจเทียบกับโค้ด OCA จริงอีกครั้งก่อนตั้งค่า

- **การส่งต่อการอนุมัติ (Forward):** เปิดใช้ด้วยฟิลด์ `tier.definition.has_forward = True` (โมดูล `base_tier_validation_forward`) เมื่อเปิดแล้วผู้อนุมัติที่ถูกคาดหวังจะเห็นปุ่ม **Forward** และกดส่งต่อการอนุมัติให้ผู้ใช้อื่นที่อยู่ในกลุ่มผู้อนุมัติแทนได้ — ไม่เขียนโค้ดใหม่
- **ผลกระทบต่อกลไกเดิม:** เลิกใช้ฟิลด์ `first_approver_id` เป็นตัวตัดสินเส้นทาง และเลิกใช้ `second_approval_state` เป็นกลไกหลัก (คงฟิลด์ไว้เพื่อความเข้ากันได้ของข้อมูลเท่านั้น)
- **สถานะรออนุมัติของ tier validation:** `tier.validation` เก็บสถานะที่ `review_ids` / `validation_status` (ไม่ใช่ `state`) จึงต้องแมป "รอใคร" จาก `review_ids` ปัจจุบัน

## 9. บัญชีและภาษี (ใช้ของเดิมทั้งหมด)

| กรณี | กลไก | ที่มีอยู่ |
|---|---|---|
| พนักงานออกเงินเอง (`payment_mode = own_account`) | จ่ายคืนด้วย `account.payment` + reconcile กับเจ้าหนี้พนักงาน | `od19_hr_expense_thai` |
| บริษัทออกเงิน (`company_account`) | ไม่ต้องจ่ายคืน | core |
| VAT (ภาษีซื้อ) | `tax_ids` บน `hr.expense` | core + enhanced |
| ใบรับรองแทนใบเสร็จรับเงิน | `od19_document_type = payment_certificate` → บังคับ VAT = 0 | `od19_hr_expense_enhanced` |
| เบี้ยเลี้ยง ม.42(3) | `od19_is_per_diem` + วงเงิน + เหตุผลเมื่อเกินวงเงิน | `od19_hr_expense_enhanced` |
| หัก ณ ที่จ่าย (WHT) | ตามที่ `od19_hr_expense_enhanced` จัดเตรียมไว้ | `od19_hr_expense_enhanced` |
| **ค่าเดินทางตามระยะทาง (Mileage)** | `hr.expense` + product UoM = กม.; ยอด = ระยะทาง × อัตรา; ไม่มี VAT / ไม่หัก WHT | `od19_hr_expense_enhanced` (ใหม่) |

**ค่าเริ่มต้นอัตโนมัติ (งานใหม่ใน Phase 2):** เมื่อพนักงานเลือก "หมวดค่าใช้จ่าย" ให้ระบบเติม `product_id` → ดึง `tax_ids`, `od19_document_type`, บัญชีค่าใช้จ่าย ให้อัตโนมัติ โดยพนักงานเห็นเฉพาะช่องที่จำเป็น

### 9.1 Mileage — การบัญชีและภาษี

- **บัญชี:** ลงเป็นค่าใช้จ่ายเดินทาง (หมวดค่าใช้จ่ายของพนักงาน) ตามบัญชีที่ผูกกับ product หมวด Mileage — พนักงานไม่ต้องเลือกบัญชีเอง
- **VAT:** ไม่มีภาษีซื้อ (เป็นการจ่ายคืนค่าพาหนะให้พนักงาน ไม่ใช่การซื้อสินค้า/บริการที่ผู้ขายออกใบกำกับภาษี) — บังคับ `tax_ids` ว่างเมื่อเป็น Mileage
- **WHT:** ไม่หัก ณ ที่จ่าย (ไม่ใช่การจ่ายค่าบริการให้ผู้รับจ้าง)
- **การจ่ายคืน:** ใช้กลไกเดิมของ `od19_hr_expense_thai` (`own_account` → จ่ายคืน + reconcile) เหมือนค่าใช้จ่ายอื่น
- **เอกสารประกอบ:** ไม่ต้องมีใบกำกับภาษี แต่ควรเก็บ ประเภทยานพาหนะ + ป้ายทะเบียน + ต้นทาง/ปลายทาง + ระยะทาง ไว้เพื่อการตรวจสอบ
- **หมายเหตุทางภาษี:** การจ่ายคืนค่าพาหนะตามจริงเพื่อการเดินทางไปปฏิบัติงานโดยทั่วไปไม่ถือเป็นเงินได้ (ไม่ต้องหักภาษี) — **ต้องยืนยันกับฝ่ายบัญชีอีกครั้งก่อนใช้งานจริง** (ดู K8)

## 10. สิทธิ์และความปลอดภัย

- **กลุ่มพนักงาน:** ผู้ใช้ทั่วไปที่ผูก `hr.employee` ของตัวเอง (ใช้ `hr_expense.group_hr_expense_user`)
- **กลุ่มผู้อนุมัติ 3 กลุ่ม:** หัวหน้าแผนก (`hr_expense.group_hr_expense_manager`), บัญชี (`account.group_account_manager`), CEO (`Expense CEO Approver` — เพิ่มใน `od19_role_catalog`)
- **ir.rule สำหรับ portal:** ผู้ใช้พอร์ทัล (ไม่มีสิทธิ์หลังบ้าน) เห็นเฉพาะใบเบิกที่ `employee_id.user_id = user` หรือ `create_uid = user`
- **ir.rule สำหรับสมุดรถ (`od19.employee.vehicle`):** พนักงานเห็น/แก้/ลบได้เฉพาะรถที่ `employee_id` เป็นของตัวเอง; ฝ่ายที่ดูแล (หัวหน้าแผนก/บัญชี/แอดมิน) ดูได้เพื่อการตรวจสอบ
- **BOM/บันทึกความปลอดภัย:** ไม่มี credential ฝังในโค้ด; ใช้ RBAC กลางตามโครงเดิม
- **API key ของผู้ให้บริการแผนที่ (ถ้าเปิดใช้ปุ่มคำนวณระยะทาง):** เก็บในระบบตั้งค่า (system parameter / company config) และเรียกผ่าน controller ฝั่งเซิร์ฟเวอร์ — ห้ามฝังในโค้ดหรือฝั่ง client

### 11.1 บันทึก as-built (Phase 2) — การเบี่ยงจากร่างแรก

Phase 2 implement จริงบน branch `feature/od19-hr-expense-ux` (worktree แยก) มีรายละเอียดที่ต้องบันทึกเพื่อความแม่นยำ:

1. **กลไก Mileage (C6):** ใช้ `quantity` = ระยะทาง (กม.) และ `total_amount` = ระยะทาง × อัตรา เป็นแหล่งความจริง เนื่องจาก `price_unit` ของ core เป็น readonly+computed — core จะคำนวณ `price_unit` (= อัตรา/กม.) ให้เองจาก `total_amount / quantity` (สำหรับสินค้าที่ไม่มีต้นทุน) จึง **ไม่เขียน `price_unit` ตรง ๆ**
2. **หมวดค่าใช้จ่าย Mileage (C7):** ระบุด้วยธง `od19_is_mileage_category` บน `product.template`; wizard ใช้ `compute` อ่านธงนี้เพื่อสลับโหมดกรอก (จำนวนเงิน vs ระยะทาง)
3. **สินค้าหมวด Mileage (C8):** seed product "ค่าเดินทางตามระยะทาง / Mileage" (`default_code = MIL-KM`, `standard_price = 0`, UoM = กม., `can_be_expensed`, `od19_is_mileage_category`) ใน `od19_hr_expense_enhanced/data/od19_expense_category_data.xml` — ต้อง `standard_price = 0` เพื่อให้ core ไม่ทับ `total_amount`
4. **Wizard ยื่นเบิก:** โมเดล `od19.expense.quick.create` ในโมดูลใหม่ `od19_hr_expense_portal` (v `19.0.1.0.0`) พร้อมเมนู "ยื่นใบเบิกค่าใช้จ่าย"

## 14. เกณฑ์ยอมรับ (Acceptance Criteria)

- [ ] พนักงานยื่นใบเบิกได้จบใน ≤ 4 ขั้นตอน โดยไม่ต้องป้อนข้อมูลภาษีเอง
- [ ] ใบเบิกทุกใบผ่านการอนุมัติครบ 3 ชั้นตามลำดับ และข้ามขั้นไม่ได้
- [ ] มอบหมายผู้อนุมัติทำแทนได้ผ่านเมนู Tier Validation
- [ ] พนักงานที่ไม่มีสิทธิ์หลังบ้านยื่นและติดตามสถานะผ่าน portal บนมือถือได้
- [ ] เบี้ยเลี้ยง/WHT/VAT/ใบรับรองแทนใบเสร็จ ทำงานครบและถูกต้องตามหลักบัญชีไทย
- [ ] ยื่นเบิก **ค่าเดินทางตามระยะทาง (Mileage)** ได้โดยกรอกแค่ระยะทาง + รถของฉัน และยอดคำนวณถูกต้องจากอัตราต่อ กม. ของบริษัท (ไม่มี VAT/ไม่หัก WHT)
- [ ] ระบบ **จดจำรถของพนักงาน** และ **เติมรถที่ใช้ล่าสุดอัตโนมัติ** ในครั้งถัดไป พร้อมแก้ไข/เพิ่ม/ลบได้ และเห็นเฉพาะรถของตัวเอง
- [ ] จ่ายคืนพนักงานแล้วเจ้าหนี้ถูก reconcile ปิดยอดจริง
- [ ] เทสต์ T1–T11 ผ่านทั้งหมด
- [ ] ไม่มีการแก้ไขไฟล์ใน Odoo core (`odoo/`, `addons/`)
