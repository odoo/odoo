## 1. บทสรุปผู้บริหาร (Executive Summary)

ใน Odoo 19 ไม่มีแนวคิด "Is Account Control" เหมือน Odoo 15 การจัดชั้นบัญชีทำผ่านโมเดล **`account.group`** ซึ่งเป็นโมเดลแยกต่างหาก ผูกกับบัญชีด้วย **ช่วง prefix ของ `code`** (ไม่ใช่ Foreign Key)

ผลการตรวจ `odoo19_puat`:

| รายการ | ค่า |
|---|---|
| `account.group` ปัจจุบัน | **0 รายการ** |
| บัญชี `account.account` ทั้งหมด | 384 (active 346 / archive 38) |
| บัญชีที่ "ทำหน้าที่หัวข้อ" (รหัสลงท้าย `.00`) | **103** |
| ↳ ถูกใช้งานจริง → **ต้องคงเป็น `account.account`** | **17** |
| ↳ ไม่ถูกอ้างอิงเลย → เป็น candidate ของ `account.group` | **86** |

**ข้อสรุปหลัก 3 ประการ**

1. **งานนี้ไม่เร่งด่วนและไม่ควรทำพร้อม remap** — เนื่องจากใน Odoo 19 CE ประโยชน์ของ `account.group` คือการจัดกลุ่มในหน้ารายชื่อบัญชีเท่านั้น (ไม่กระทบยอดตัวเลขในรายงานการเงิน) และการแปลงหัวข้อจะ **ชนกับปลายทางของ remap 4 บัญชี** (`1111.00`, `1130.00`, `5110.00`, `5120.00`)
2. **ทำได้ แต่มีข้อจำกัดเชิงโครงสร้าง** — ผังบัญชีนี้ใช้รหัสแบบจุดทศนิยม (`1110.00`) ซึ่งลำดับชั้นเชิงความหมายไม่ตรงกับกลไก prefix แบบต่อเนื่อง ต้องออกแบบช่วง prefix เป็นชั้น ๆ (length stratification) เพื่อเลี่ยงข้อจำกัดการทับซ้อน
3. **ข้อเสนอแนะ: เลือกแนวทาง B** — คงบัญชีหัวข้อทั้ง 103 ไว้เป็น `account.account` แต่ **Archive เฉพาะตัวที่ไม่ใช้งาน (86)** และสร้าง `account.group` เพียง 5 กลุ่มบนสุด (1000–5000) เพื่อไม่ให้เสีย XML ID `__import15__` และลดความเสี่ยง

## 7. ขอบเขตงานและลำดับการดำเนินการ

### 7.1 ลำดับที่ตกลง (ต้องทำตามลำดับนี้)

```
[1] สำรอง DB (pg_dump odoo19_puat)
        ↓
[2] รัน remap_accounts.py  (DRY-RUN → ตรวจ → WRITE)
        ↓
[3] ตรวจสอบผล remap (config คงเหลือ = 0)
        ↓
[4] ทบทวนเอกสารนี้ + เลือกแนวทาง (A / B / C)
        ↓
[5] (ถ้าเลือก) สำรอง DB อีกครั้ง → รันสคริปต์ group (DRY-RUN → WRITE)
```

### 7.2 ขอบเขตงาน (เฉพาะแนวทาง B — ที่เสนอ)

1. เขียนสคริปต์ใหม่ `migration/cleanup/to_account_group.py` (แยกจาก `remap_accounts.py`)
2. Archive บัญชีหัวข้อที่ไม่ใช้งาน 86 รายการ (`active=False` — ไม่ลบ)
3. สร้าง `account.group` 5 กลุ่มบนสุดตาม §5.1
4. Unit/DRY-RUN verification: ตรวจ `group_id` ของบัญชี leaf ต้อง map ถูก
5. สำรอง DB → รัน DRY-RUN → ตรวจ → รันจริง

### 7.3 ขอบเขตงาน (แนวทาง C — เต็มรูปแบบ)

เพิ่มจาก B: ลบ 86 บัญชี + สร้าง group ครบทุกระดับ (§5.1–5.4) — ต้องออกแบบช่วง prefix ให้ครบก่อน + ทดสอบบนสำเนา

## 8. เกณฑ์ตัดสินใจ (GO / NO-GO)

| เกณฑ์ | เงื่อนไข GO |
|---|---|
| remap เสร็จสมบูรณ์ | config คงเหลือ = 0 จุด |
| ฝ่ายบัญชียืนยันช่วง prefix | ลงนามใน §5 |
| สำรอง DB | มีไฟล์ dump ก่อนรัน |
| ผ่าน DRY-RUN | ไม่มี ValidationError + group_id ถูกต้อง |
| ไม่มี XML ID dependency | ยืนยันว่าไม่มีระบบอื่นอ้าง `__import15__` |

**คำแนะนำสรุป**: เริ่มจากแนวทาง **B** เพื่อความปลอดภัย และ **ทำหลังจาก remap เสร็จเรียบร้อยแล้ว**
